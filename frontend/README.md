# NovaLink — витрина магазина

Next.js 16 (App Router) · React 19 · Tailwind CSS 4. Данные берутся из API в `../backend`.

## Запуск

```bash
npm install
cp .env.example .env.local   # адрес API, по умолчанию http://localhost:4000/api
npm run dev                  # http://localhost:3000
```

Бэкенд должен быть запущен (см. `../backend/README.md`).

Сборка в API не ходит: главная помечена `dynamic = "force-dynamic"` и
рендерится на каждый запрос, остальные страницы зависят от параметров адреса.
Благодаря этому образ собирается без доступной базы.

## Деплой

Витрина собирается в `output: "standalone"` и запускается из `Dockerfile`
рядом с API и nginx — весь стек описан в [DEPLOY.md](../DEPLOY.md).

`NEXT_PUBLIC_API_URL` попадает в браузерный код **на этапе сборки** (в Docker —
аргумент сборки). Относительное значение `/api` означает «API на том же
домене»: тогда фото берутся с текущего домена и образ не привязан к доменному
имени. `API_URL` читается уже при запуске — это внутренний адрес API для
серверного рендеринга (в Docker `http://api:4000/api`).

## Страницы

| Путь | Что там |
| --- | --- |
| `/` | слайдер из баннеров админки (смена каждые 3 с, свайп), категории, популярные товары, промо-блоки |
| `/catalog` | каталог: `category`, `search`, `brand`, `min`, `max`, `stock=1`, `sort`, `page` |
| `/product/[slug]` | галерея, цена, характеристики по группам, похожие товары |
| `/cart`, `/checkout` | корзина и оформление заказа (отправляется в API, цены и остатки проверяет бэкенд) |
| `/favorites` | избранное |
| `/help` | доставка, гарантия, трейд-ин, контакты (тексты-заготовки) |

## Админка

`/admin` — вход по логину и паролю администратора (по умолчанию `admin` / `admin12345`, задаются `ADMIN_LOGIN` / `ADMIN_PASSWORD` в бэкенде при `npm run db:seed`).

| Путь | Что там |
| --- | --- |
| `/admin` | обзор: новые заказы, счётчики, новые товары и закончившиеся |
| `/admin/orders` | заказы с фильтром по статусу и поиском по номеру, имени, телефону |
| `/admin/orders/[id]` | состав заказа, контакты, адрес; смена статуса (отмена возвращает товары на склад) |
| `/admin/products` | список с поиском и фильтрами; остаток, «на витрине» и «хит» меняются прямо в таблице |
| `/admin/products/new`, `/admin/products/[id]` | товар: цены, склад, категория, бренд, фото (загрузка и порядок), характеристики |
| `/admin/categories` | дерево категорий, создание и редактирование |
| `/admin/brands` | бренды с логотипами |
| `/admin/banners` | слайды на главной (до 5): товар, метка, заголовок, картинка, порядок, вкл/выкл |
| `/admin/users` | сотрудники: логин, имя, роль, пароль (только для администратора) |
| `/admin/settings` | уведомления о заказах в Telegram (администратор) и смена своего пароля |

JWT хранится в httpOnly-cookie, все запросы к API и изменения идут с сервера Next (Server Actions в `src/app/admin/actions.ts`). После изменений витрина обновляется сразу.

Роли: **менеджер** ведёт каталог, баннеры и заказы; **администратор** дополнительно заводит сотрудников и настраивает магазин — эти разделы менеджеру не показываются, а API отвечает на них `403`. Смена пароля закрывает сессии на других устройствах, текущая продолжает работать.

Telegram-бота подключает сам владелец магазина в `/admin/settings`: вставляет токен от `@BotFather`, нажимает «Определить чат» (бот подскажет, куда писал), включает уведомления и проверяет кнопкой «Отправить тест». Токен хранится в базе и наружу не отдаётся — в форме виден только его хвост.

## Устройство

- `src/app/(shop)/` — страницы магазина с шапкой и подвалом, `src/app/admin/` — админка со своим макетом и боковой панелью.
- `src/app/globals.css` — дизайн-токены (цвета, шрифтовая шкала 48/32/24/18/16/14, радиусы 12/8) и тёмная тема через `data-theme` на `<html>`.
- `src/lib/api.ts` — запросы к API (только на сервере), `src/lib/types.ts` — типы ответов.
- `src/lib/store.ts` — корзина и избранное в `localStorage`.
- `src/components/` — шапка, подвал, карточка товара, кнопки, иконки.
- Пока у товара нет фото, вместо него рисуется нейтральный силуэт устройства по категории.
